# 启用开关点击后页面跳动：修复记录

日期：2026-11-07。仅修改前端的开关更新路径，后端和数据库结构未改动。

## 原因与修复

原先列表和详情页开关都调用通用 `mutate()`。PATCH 成功后递增 `reload`：

1. 列表进入 loading 分支，整张表被卸载，页面高度临时缩小，浏览器强制收缩滚动位置。
2. 重新 GET 列表按 updated_at 倒序返回，刚点击的行移到最上面。
3. 详情也被清空为加载界面，存在同类跳动。

现增加专门的 `toggleFlag()`：

- PATCH 成功后使用服务端返回的 Flag，原地替换对应记录；其他行保持原位置与对象引用。
- 不触发列表重新加载，不卸载表格，也不按更新时间重新排序。
- 详情页保留当前内容，后台刷新完整详情，以更新真实操作历史。
- 保存失败不提前改变开关状态；若状态已保存但历史刷新失败，提示与事实相符。
- 搜索条件和筛选条件保持不变。若启用状态筛选使某条记录不再符合条件，它仍会正常从筛选结果中移除。
- 用户主动点“刷新”或重新打开页面时，仍采用后端返回的最新排序。

## 实测

### 修复前

1024×600 视口，页面已滚动，点击专用 staging 演示 Flag 的开关：

- scrollTop：320 → 213.5。
- 该 Flag 从第 4 行移动到第 1 行。

### 修复后

使用截图定位的原位坐标点击，不调用会自动滚动定位元素的点击助手，连续切换三次：

| 状态 | scrollTop | 文档高度 | 按钮距视口顶部 |
|---|---:|---:|---:|
| 初始 false | 453 | 1185 | 291.5546875 |
| 点击后 true | 453 | 1185 | 291.5546875 |
| 再次点击 false | 453 | 1185 | 291.5546875 |
| 再次点击 true | 453 | 1185 | 291.5546875 |

四次测量的完整行顺序一致。原始浏览器测量见 `test-results/scroll-fix-browser.json`。其中单独保留了定位器点击自动滚动的测量，不把自动化工具的定位动作误当作应用跳动。

详情页启停也已验证：操作历史数量从 12 → 13 → 14，开关及提示同步更新。测试专用 Flag 的启用状态已恢复到测试前状态；新增历史为真实测试操作，不删除审计记录。

- `npm test`：6 项通过，退出 0（新增 3 项顺序 / 状态更新回归测试）。
- `npm run build`：通过，退出 0。
- 浏览器 error / warn 捕获结果为空。
- 原始日志：`test-results/scroll-fix-web-test.log`、`test-results/scroll-fix-web-build.log`。
